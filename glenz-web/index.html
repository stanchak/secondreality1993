╤══════════════════════════════════════════════════════╤

[ WHAT IS THIS ]

A faithful port of the glenz vectors part of Second Reality — the demo Future Crew won Assembly '93 with. It's built from the original C + x86 assembly source, released into the public domain for the demo's 20th anniversary (2013). This runs the actual program logic — not a lookalike reimplementation.

╤══════════════════════════════════════════════════════╤

[ GRAPHICS ]

> Virtual VGA. A 320×200 mode-13h indexed framebuffer with a 256-entry 6-bit palette, shown through a WebGL palette-lookup shader.

> The "transparent new copper". Polygon edges become per-scanline XOR color transitions; consecutive frames are diffed and only the changed spans are written. Glenz transparency = every visible face gets a dynamically allocated 16-entry palette block of face-brightness + background/4.

> Live physics. The jello drop & squash is real integer physics with the original's truncation quirks — the splat is a view-space Y-clamp, not a canned animation.

╤══════════════════════════════════════════════════════╤

[ THREE.JS AS THE MONITOR ]

Here's the twist: three.js doesn't draw the vectors. The whole polygon & span pipeline runs on the CPU into an indexed framebuffer — faithful to the original's software renderer. Three.js plays the part of the VGA hardware:

> the 320×N index buffer is uploaded as a DataTexture (one 8-bit channel);

> the 256-entry 6-bit DAC palette is a second 256×1 texture;

> a fullscreen quad + fragment shader does the palette lookup per pixel — index → DAC → RGB — the exact path a real mode-13h VGA card took, now on the GPU. Nearest-filtering keeps the chunky pixels razor-sharp.

So the GPU is emulating a 1993 monitor, not rendering 3D — which is what makes the output pixel-for-pixel what a DOS PC would have shown.

╤══════════════════════════════════════════════════════╤

[ MUSIC — THE FUN PART ]

The song is "UnreaL ][" by Purple Motion. But the MUSIC1.S3M in the source tree is booby-trapped: its pattern data is XOR-scrambled on disk — Future Crew's anti-ripping protection. Play the raw file and you get random notes on real instruments. The descrambler lived inside FC's private music player.

> We ship FC's scrambled file verbatim and descramble it live in your browser — exactly as the demo did in 1993.

> The XOR keystream was reconstructed from the scrambled files alone (no clean copy), by constraint-solving the S3M format. It reproduces the officially released clean song byte-for-byte.

▸ Open DevTools → Console (F12) and reload to watch the descramble happen on load: scrambled bytes XOR keystream = real notes.
╤══════════════════════════════════════════════════════╤

[ SYNC ]

The S3M order list carries +++ markers at section boundaries; the demo's interrupt server counts music rows to them. A 70 Hz virtual vblank clock is anchored to the audio clock — the same master-clock trick the original used. The wipe fires 6.5 s in, the ball hits the pedestal right on a section change, and the part exits where the dot tunnel takes over in the full demo.
